# 移动端商品展示与筛选页面 - 详细实施计划

本文档为 AI 开发者提供分步实施指令。请严格按照以下步骤顺序执行，在进入下一步之前，必须确保当前步骤的验证测试已完全通过。**严禁在执行前输出任何代码实现，仅作为行动指南。**

---

## 阶段 1：项目初始化与基础配置

### 步骤 1.1：创建项目骨架
- **指令**：使用 Vite 模板创建一个新的 React + TypeScript 项目。项目名称应与当前目录结构兼容。
- **验证**：运行本地开发服务器，确保能在浏览器中看到 Vite 默认启动页。

### 步骤 1.2：配置 Tailwind CSS
- **指令**：在项目中安装并初始化 Tailwind CSS 及其相关依赖（PostCSS、Autoprefixer）。配置 Tailwind 的配置文件，确保它能扫描到所有的 React 组件文件。
- **验证**：在根组件（如 App.tsx）中添加一个带有 Tailwind 颜色背景和边距的元素，启动服务器验证样式是否生效。

### 步骤 1.3：配置移动端优先的基础样式
- **指令**：在全局 CSS 文件（如 index.css）中，清除默认的内外边距。针对 `body` 或顶层根容器，设置最大宽度（例如 `max-width: 480px`），并在水平方向居中（`margin: 0 auto`），同时隐藏横向滚动条，模拟手机端视口。
- **验证**：在 PC 浏览器中打开页面，验证内容区域是否被限制在屏幕中央，且表现出类似手机的窄屏布局。

### 步骤 1.4：搭建目录结构与移入 Mock 数据
- **指令**：按照技术栈文档中的建议，在 `src` 目录下创建 `components`、`hooks`、`mocks` 等空文件夹。将之前生成的 `mockData.ts` 文件完整移入 `mocks` 文件夹中。
- **验证**：在根组件中尝试导入 `mockData.ts` 中的变量并进行控制台打印，确保路径和类型定义无误。

## 阶段 2：静态 UI 组件开发

### 步骤 2.1：开发 Header 组件
- **指令**：在 components 目录下创建 Header 组件。实现顶部标题（如“补贴专区”）和下方的活动标签栏。活动标签栏必须使用 Flexbox 实现横向排列，且内容超出时允许横向滚动（隐藏滚动条）。
- **验证**：在 App.tsx 中引入 Header，在移动端视图（或受限宽度的 PC 视图）中滑动标签栏，验证其是否能平滑横向滚动。

### 步骤 2.2：开发主体布局容器 (ContentLayout)
- **指令**：创建 ContentLayout 组件。使用 Flexbox 实现左右分栏布局。左侧固定宽度（用于侧边栏），右侧占据剩余空间（`flex: 1`，用于商品列表）。确保这两个区域都能独立进行垂直滚动。
- **验证**：在左右两个区域分别放入足够高的占位内容，验证它们是否能各自垂直滚动，且互不影响。

### 步骤 2.3：开发左侧 Sidebar 组件
- **指令**：创建 Sidebar 组件。接收 Mock 数据中的品牌列表进行渲染。实现垂直列表布局，并定义选中状态和未选中状态的 Tailwind 样式差异（如背景色、文字颜色或左侧指示条）。暂时使用内部状态或硬编码测试选中效果。
- **验证**：点击不同的品牌项，验证高亮样式是否能正确切换。

### 步骤 2.4：开发单个 ProductCard 组件
- **指令**：创建 ProductCard 组件。接收单个商品数据作为属性。使用 Flexbox 布局实现左图右文（或上图下文，参照需求截图）。实现图片懒加载属性（`loading="lazy"`）。分别渲染商品标题、标题行内标签、下方的服务标签以及价格和按钮。
- **验证**：传入一条 Mock 数据，验证卡片渲染的布局、颜色和间距是否与需求截图的视觉层级一致。

## 阶段 3：核心逻辑与状态管理接入

### 步骤 3.1：在根组件建立全局状态
- **指令**：在 App.tsx 中初始化两个核心状态：`currentBrand`（当前选中的品牌 ID，初始为空或特殊值代表“全部”）和 `visibleProducts`（当前应该渲染在列表中的商品数组）。
- **验证**：通过 React DevTools 检查 App 组件，确认初始状态已正确挂载。

### 步骤 3.2：实现品牌筛选联动
- **指令**：将 `currentBrand` 状态和更新函数传递给 Sidebar 组件。当 Sidebar 触发点击时，更新 `currentBrand`。使用 `useMemo` 或 `useEffect` 监听 `currentBrand` 的变化，从全量 Mock 数据中过滤出对应的商品数组。
- **验证**：点击侧边栏不同的品牌，在控制台打印过滤后的商品数组，验证数据是否正确对应。

### 步骤 3.3：实现商品列表的初始分页渲染
- **指令**：修改 `visibleProducts` 的逻辑。无论是初始全量数据还是过滤后的品牌数据，首次仅截取前 N 条数据（N 约等于 1.5 屏幕高度所需的卡片数量，如 6-8 条）赋值给 `visibleProducts` 进行渲染。
- **验证**：刷新页面或切换品牌时，检查右侧商品列表渲染的 DOM 节点数量，确保没有一次性渲染所有过滤后的数据。

## 阶段 4：交互功能增强

### 步骤 4.1：实现 IntersectionObserver 触底加载 (无限滚动)
- **指令**：在 hooks 目录下创建一个自定义 Hook（如 `useInfiniteScroll`），封装 `IntersectionObserver` 逻辑。在 ProductList 组件的底部添加一个隐藏的“哨兵” DOM 节点。当哨兵节点进入视口时，触发回调，从当前过滤后的数据源中截取下一批数据追加到 `visibleProducts` 中。
- **验证**：在右侧列表向下滚动，当到达底部时，验证列表中是否动态增加了新的商品卡片，直至所有该品牌下的商品加载完毕。

### 步骤 4.2：实现回到顶部功能 (BackToTop)
- **指令**：创建 BackToTop 组件。监听右侧商品列表容器（或 window，取决于滚动容器设定）的 `scroll` 事件。当滚动距离超过视口高度时，显示悬浮按钮。点击该按钮时，触发平滑滚动将容器的 `scrollTop` 归零。
- **验证**：向下滚动超过一屏，验证按钮是否出现；点击按钮，验证列表是否平滑滚动到顶部；滚动回顶部后，验证按钮是否消失。

### 步骤 4.3：完善品牌切换时的滚动重置
- **指令**：在 App.tsx 或 ProductList 组件中补充逻辑：每当 `currentBrand` 发生变化时，除了重置渲染的数据，还必须强制将右侧商品列表容器的滚动条重置回顶部。
- **验证**：在某个品牌下滚动到列表底部，然后点击侧边栏切换到另一个品牌，验证右侧列表是否处于最顶部位置，而不是停留在之前的滚动深度。
